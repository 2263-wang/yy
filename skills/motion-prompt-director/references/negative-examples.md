# 反面案例：两轮实做里踩过的坑

本目录收录同一素材（六张专辑海报）先后两轮实做的失败记录，附实测数据与代码层证据。

- **第一轮（四个视频版本）**：目标是一支 6 秒揭示动效。四次尝试分别踩了"两端平滑的飘、有速度没物理、叙事对了物理全丢、指标过了观感未验"。
- **第二轮（换纸面拼贴质感，见文末）**：前四类没复发，但出现了架构级新错（把画幅当画布）和一批元素级细节错。

**收录理由**：正确范例只说明"应该长什么样"，失败案例才能防住"具体会怎么错"。这里每一个都不是审美问题，是流程问题。

---

## 共同结论

> **动画流程过于僵硬，整体展现没有完全按照标准逻辑去走。**

这句话是用户对四版成片的统一判断。拆开看，"僵硬"和"没按标准逻辑"是两件事，但同源：

| 表面症状 | 实际病因 |
|---|---|
| 动作"飘"、"浮"、"像贴纸" | 缺蓄力、缺收尾、缺挤压——运动没有力的痕迹 |
| 主体不突出，看完记不住 | 没有先定"记忆点那一拍"，动作平均分配 |
| 节奏平、看不出高潮 | 节拍没有信息增益排序，每一拍都在做同样的事 |
| 交付即"完成" | 停在第一个"看起来完成了"的地方，不回头量化 |

**标准逻辑应当是**：定情绪与记忆点 → 排节拍（每拍填"观众多知道了什么"）→ 写贯穿全片的机位曲线 → 落物理（蓄力/缓动/跟随/挤压）→ 用指标验收 → 人眼确认。
**实际流程是**：拿素材 → 想个大概效果 → 写代码 → 渲一版看着差不多 → 交付。

跳过的是第 1 步、第 2 步和第 5 步。

---

## 两个独立的失败轴

四个版本分布在两条轴上，互不替代——这是本组案例最重要的发现：

| 版本 | 叙事（主角怎么被引出） | 运动质量（有没有力） | 指标验收 |
|---|---|---|---|
| v1 爆开跳出来 | 差：无铺垫，主角突兀跳出 | 差：双向平滑，软 | 未做 |
| v2 爆发冲击 | 差：仍是硬插主角 | 中：有快起，无挤压无弧 | 未做 |
| v3 揭开主角 | **好：层层揭示，有悬念** | **零：物理全丢** | 未做 |
| v4 指标修复 | 好（沿用 v3） | 中上：五项达标 | 做了 |

**结论：叙事对了不等于动作对（v3），动作有劲也不等于叙事对（v2）。** 两件事必须同时成立，而前三次尝试总在补齐一边时丢掉另一边。真正的问题不在某一版的手法，在于没有把这两条轴当成并列的验收项。

---

## v1-explode-jump.mp4 — 首版：两端平滑的"飘"

- **设计意图**：卡片从中心散开成 3×2 网格 → 相机呼吸推进 → 主角抬升。
- **实际做法**：`smoothStep` 做所有位移（两端速度都为 0）；蓄力只回缩 8px；给每张卡硬加正弦弧偏移，偶数卡向上、奇数卡向下；主角用 `smoothStep` 放大。
- **病灶**：
  1. 所有动作两端都慢 → 全程"飘"，没有一处有力；
  2. 蓄力 8px 在 302px 的卡片上肉眼不可见，等于没有；
  3. 强制正弦弧让六张卡整齐划一地上下摆，反而更机械——弧线成了装饰，不是运动结果；
  4. 主角靠 `smoothStep` 匀速放大，是"浮"起来，不是"跳"出来。
- **判定依据**：用户原话"连初学者都不如"。
- **代码已覆盖，无实测数字。**

## v2-burst-impact.mp4 — 二版：有速度，没物理

- **设计意图**：按"爆发/冲击"重做，记忆点是主角跳出来。
- **改进**：位移改用 `burstOut`（快起）；六张卡先聚成一叠再炸开；错峰改为不规则，倾角加大。
- **仍在犯的错**：
  1. 全程无挤压拉伸（`squash` 未引入）；
  2. 路径仍是直线，没有弧；
  3. "主角跳出来"的过冲公式形同虚设（与 v3 同一类错误，见下）；
  4. **叙事仍是硬插**：卡片散开后主角直接放大，观众不知道为什么是它。
- **判定**：动作比 v1 有劲，但"主角怎么被引出来"这个问题没解决。
- **代码已覆盖，无实测数字。**

## v3-reveal-zero-physics.mp4 — 三版：叙事对了，物理全丢

- **设计意图**（用户提出）：卡片飞入叠成一摞，主角垫底 → 上面的卡依次向四周划开 → 露出主角的同时放大 → 其余卡缩小降透明度。
- **叙事评价**：**这是四版里最好的一次设计**。它解决了 v1/v2 都没解决的问题——主角不是硬跳出来的，是被层层揭开、水到渠成地成为焦点，观众有"原来藏的是它"的揭示感。
- **致命缺陷**：实现时把运动质量整个丢掉了。
  - `grep -n "squash\|arc\|anticip"` 在组件里 **零命中**；
  - 划开是纯直线平移：`slideX = centerX + dir.dx * dist * slide`，x 与 y 共用同一进度，无垂直分量；
  - 旋转与位移同帧到位，无跟随滞后；
  - 无蓄力，"压着的卡"是直接弹开的。
- **为什么会发生**：注意力全在"叙事怎么排"，把上一版已有的 `squash`、`arcOffset` 全部弃用，且**没有回头核对**。
- **判定依据**：用户"感觉僵硬"——僵硬的原因在代码里，不在审美上。

## v4-metric-passed.mp4 — 四版：指标过了，观感未验

- **改进**：把轨迹与曲线抽到 `motion-curves.js`，渲染与审计共用；重新引入蓄力、弧线、挤压、旋转滞后；主角放大改用阻尼阶跃。
- **实测（审计脚本 `audit.mjs`，与渲染同一份函数）**：

| 指标 | v3 | v4 | 判据 |
|---|---|---|---|
| 弧线度 | 0% | **13.5%** | ≥5% |
| 蓄力反压 | 0 | **4.7% 行程** | 3–6% |
| 挤压峰值 | 0 | **6.9% / 9.8%** | 有且面积近似守恒 |
| 静止残留变形 | — | **0.00%** | ≈0 |
| 旋转滞后 | 0 帧 | **3 帧** | 1–3 帧 |
| 起步速度 | — | **47px/帧（12%行程）** | 不得独占首帧 |
| 主角过冲 | — | **8.4%，终点精确 1.750** | >3% 且归位 |

- **两个必须记下的教训**：
  1. **公式像什么，不等于产生什么。** 中途写过一版过冲公式 `1-(1-p)³ + 0.085·sin(πp)·e^(-3p)`，形式上是"冲过再回落"，实测量出来 **0.1%**——因为基础曲线到 p=1 才到 1，而 `sin(πp)` 在 p=1 恰好为 0，两项叠不出超过 1 的值。**没有量化就宣布修好，等于没修。**
  2. **指标全绿不等于好看。** 本版只做了公式层审计，未做像素层（隔离单卡测包围盒）验证，也未经人眼确认。它证明的是"运动符合判据"，不是"画面对"。

---

## 可直接复用的五条

1. **先定记忆点，再排动作。** 整段只有一拍是高潮，其余为铺垫。四个版本里三次栽在"动作平均分配"。
2. **"看起来完成了"不是完成标准。** 三次都是看一眼接触表/静帧就交付。交付前必须跑一次量化。
3. **叙事与运动是两条独立轴，不能互补。** 补了一边要回头确认另一边没丢（v3 就是补叙事时把物理丢了）。
4. **弧线是运动的结果，不是贴上去的装饰。** 给每个元素硬加正弦偏移，会得到整齐的机械波浪。
5. **写任何"过冲/回弹"公式后立刻量峰值。** 实测峰值不超过目标值，这个过冲就不存在。

# 第二轮：纸面拼贴版（换风格时复发的老毛病 + 一个新种类的错）

同一套内容换成"纸面 / 手绘 / 教学"质感重做，前四类错误没有复发，但出现了**一批新的、形态不同的错**。清单在这里，因为它们比六海报那四个更容易复发——**它们都藏在细节里，看一眼接触表发现不了**。

## A. 架构级错误（最严重，导致整轮返工）

| 症状 | 病因 | 修法 |
|---|---|---|
| 三种转场做法全部失败 | **把输出画幅当成了画布**，于是任何段落转移都只能靠转场去遮 | 改成世界 + 取景框 + 摄像机路线。见 `world-and-camera.md` |
| 移动途中出现大片空白纸 | 站点间距 2177px，远超 `取景框宽/2 + 前站内容半径` | 收到 0.8–0.9×宽，让两站内容在投影上重叠 |
| 移动帧一片灰白 | 模糊按手感给了 30px，3.5px 的网格线被抹平 | 上限 = 最细线宽 × 4 = 14px |
| 同一张主角卡在两站同时出现 | 后一站也摆了一份同图，镜头走过去时两张并排在画面里 | 后一站那张等镜头到位再入场 |

**这一类错误的共同特征：单看任意一站都完全正常，只有拼起来（或镜头移动时）才暴露。** 所以验收必须包含"过渡段的中点帧"，不能只验停站帧。

## B. 元素级错误（一对一，都能定位）

| 症状 | 病因 |
|---|---|
| 光标悬在空处、不贴卡片 | 光标走独立的平滑插值路径，卡片走过冲曲线，两者中途脱节。**光标必须从卡片状态直接取值** |
| 叠摞看不出是六张 | 每张只错开 5.5px / 4.2px，透明度都接近 1，视觉上等于一张 |
| 黄线只有右上半截 | 以中心为原点、只往一个方向长。改成用 SVG 明确算两个端点 |
| 圈注切掉卡片四角 | 用椭圆套矩形。改手绘感圆角矩形描边 |
| 圈注整体偏心 | 缩放以中心为原点，但锚点跟着 `宽×scale/2` 走。位置不能跟尺寸走 |
| 标题页能量 0.00 | 整页静止。数字卡只下落 54px，等于没动——改成从 380px 真正落下 |
| "11°"标注被 SVG 裁掉 | 文本 y 坐标是负数，落在 viewBox 外。内部整体下移留余量 |
| 结尾"全景"读不出来 | 相机退到 0.68，但主角仍保持 1.5×，把网格中央挡住了 |
| 数字卡与纸片重叠 | 坐标单独调，没有做元素间距检查 |

## C. 一条新增的硬教训

> **"这个动作方向相反的两件事同时发生，会互相抵消。"**

结尾原本让主角放大和相机后退同时跑。一个向前一个向后，观感上主角大小几乎没变——**观众读到的是"什么都没发生"**。实测能量只有 2.88，而相机那一拍是 7.81。

改成主角先冲高 0.4s，相机延后 0.4s 才开始退，结尾立刻变成清晰的两拍。

**自查方法**：任何时刻，如果有两个动作对同一个视觉量（大小、位置、亮度）的作用方向相反，必须错开时间。
