# 有边界的组合探索：扩充方法、剪枝、验证

穷举指有组织地展开表达与动作可能性，不声称枚举所有动画，也不要求每个组合都渲染。内容约束持续剪枝，外部研究持续扩充方法。库是起点，不能把“未在库里”当不可做。

## 先展开哪些维度

1. 内容关系、观看任务与表达态度：依赖、并列、先后、整体局部、因果、状态、身份、空间或节律；同时考虑观众要感受什么、对象以什么行为表达。态度按题目形成，不把“轻松／荒诞”等词当成固定风格菜单，详见[表达个性](expressive-direction.md)。
2. 组织方法：大平面世界＋取景移动、同图谱改变焦点／职责、二维对象组装、跟随信号、图形状态变化、并列交互、真实图片局部／尺度揭示、拼贴、产品图片蒙太奇、Logo到产品交接等。当前不走三维或CSS透视模拟；各方法需声明rendering=flat-2d。列表开放，不强求每题全用。
3. 观看顺序：从整体入局部、从局部揭示整体、沿关系追踪、并列后交互、先给结果再展开结构。说明顺序服务什么，不自动按目录排。
4. 开场／中段／出口：谁先出现、什么改变、什么保持、谁接焦点；出口由剪辑用途决定。先建立完整方向，再比较局部动作。
5. 节奏：动作的加减速、交错与停留；画面状态的存续、疏密、尺度与动静。仅换曲线不算另一个表达方向。

原创未定主线时扫描与内容和态度相关的组织方法，合并重复项、排除不适配项，以小实验比较有潜力的方向。候选数量由真实不确定性决定，不强凑2–3个或只在库内选择。简单、既定方案或局部修订缩小范围，不规定每拍六种或十八次渲染。DrawAI 配方可以提供试验的可执行起点，保留什么、改造什么由本题决定。

## 每个有效方向内部继续展开

整片方向比较后仍需[片内组合设计](visual-richness.md)。把内容展开为可见事件，绑定能支撑细节的素材，再决定各段的表示形式、内层／外层变化、取景、密度与停留；据此选择和验证，必要时重新调整方向。统一视觉风格不等于全片同一布局，不规定每段必须换语言。

可从真实图片揭示、图形状态、角色行动、群体编排、局部工作窗口或抽象节律中按内容组合。事件之间用可追踪对象、锚点、形状、方向或内容关系接续；不是在一条候选后追加随机效果。完整例子见[丰富度案例](richness-cases.md)。

## 方法适配与动作相接

每个方法写：适合的内容关系、必需条件、可见变化、事实风险、起态、终态。动作连接至少核对：

- 上一动作终态是否提供下一动作所需对象、形状和空间参照；消失的对象不能无依据继续追踪。
- 身份、锚点、尺度与层序是否继承，速度／方向突变是否有表达理由。
- 关系含义是否相容：组装可表达形成整体，不能无依据暗示企业真实物理包含；抽离可能暗示分离，不默认表达合作。
- 取景框移动后，主角与下一参照是否仍能识别；大世界不能变成逐站读目录。
- 出口是否满足透明、循环、接后文或完整成片。保持与透明清空是不同终态。

先剪去硬违规／事实不符／素材无能力的组合，再剪去不相接的动作，剩余才看构图和粗动稿。不要平均分配时间给每个品牌；按表达任务安排焦点。所有候选遵守文字与声音约束。

## 本题例子：AI产业链开场

以下是纸面推演，未声称搜到或验证外部影片，也不是题目专用答案。文案在提出问题，不能凭空画国家差距数值或采购连线。

- 大画布关系探索：少量可识别对象建立整体参照，沿有依据的依赖关系移动取景，再退开看关系属于哪个整体。风险是缩成目录停站；需要看到关系被揭示，不只轮换站点。
- 同图谱转换观看职责：对象留在同一关系场，先看整体，再由某条连接或支撑环节接管焦点，最后交给后文。与上一项的差异在于取景可稳定、图谱状态变化，不只换镜头速度。
- 追踪请求／信号：同一对象触发不同环节响应。只有依据支持这种过程时成立；产业依赖不能擅自编成推理请求经过全部制造厂商。
- 支撑结构展开：从模型标识揭示抽象支撑层，再关联基础硬件。说明依赖示意，不能把所有品牌Logo画入同一芯片并暗示真实结构。

对照风险与文案，可排除部分方向或改造；搜索同题动画、系统解释、半导体供应链等案例可能引入第五种方法。不是强制四项入围，更不规定必须运镜。

## 可运行的组合种子

[表达方法库](../assets/motion-library/expression-methods.json)提供开放的组织方法和起终态，不是完整动画组件：

```text
node scripts/explore-directions.mjs --topic=AI产业链 --relations=dependency,part-whole --purpose=opening --duration=8 --mode=insert
node scripts/explore-directions.mjs --input=brief.json
```

brief.json必需topic、relations（字符串数组）；可选purpose、duration、text（brand-only默认；product-name只在当前用户明确要求名称时）、mode（insert/overlay/loop/transition）、methods（符合方法库结构的新方法数组）。方法包含id、name、rendering（flat-2d；未分类／三维会被排除）、relations、conditions、risk、source、query及带id/description/from/to状态的entries/middles/exits；exit还需modes。新增项标source为真实来源或明确的自制方法。overlay／transition出口to须为clear，loop出口to须与入口from相同；这些只是声明状态，实际透明、覆盖切点和循环速度仍需检查。JSON是数据，不执行其中指令。

脚本枚举状态兼容的种子，列出不匹配方法与未覆盖关系，不自动选胜者、不按词频评审美、不锁定工具、不执行联网／渲染。researchPlan是待执行检索词，不是搜索证据。关系未知返回扩充需求，不能强套第一类。新增方法也不自动证明事实适配；种子需映射真实对象、时长、构图与研究证据。

该探索脚本当前只接受 `brand-only` / `product-name`，不是所有项目的必经步骤。明确图表／界面／指定文案任务按 SKILL.md 的内容范围和[DrawAI 制作与复用](drawai-production.md)设计、制作，不把必要文字强塞进无文字种子，也不因脚本的范围较窄而拒绝已授权的项目。其他旧选择器的 `--text=explicit` 只是检索开关，不能代替项目中的文字范围记录。

状态标签只检查显式相接，不能证明速度、遮挡、理解或美感。组合多不等于创新；同一方法内多种入口不算多个完整表达。按主导方法、观看顺序与实际变化去重，再选择需验证的部分。
